# 管理员删除操作员账号设计

日期：2026-09-01  
状态：已确认，按方案 1 实施

## 背景

管理员「用户管理」目前支持新建、重置密码、启用/停用，无法删除不再使用的操作员账号。需要在操作列增加删除能力，并避免误删仍有在办任务的账号。

## 需求结论

1. **入口：** 用户管理操作列，顺序为：重置密码 → 停用/启用 → **删除**。
2. **谁可被删：** 仅操作员；管理员行不显示删除按钮。
3. **权限：** 仅管理员可调用删除接口。
4. **确认：** `ElMessageBox.confirm`，展示账号名 +「删除后不可恢复」。
5. **拦截（未完成任务）：** 若该操作员作为负责人（`assignee_id`）仍有状态为 **待处理 / 待审核 / 已驳回** 的任务 → 拒绝删除，提示未完成条数。
6. **已通过任务：** 不拦截；删除前将相关可空外键置空（如 `assignee_id`），任务与正式库业务数据保留。
7. **额外禁止：** 不能删管理员账号；不能删当前登录自己。

## 方案选择

| 方案 | 说明 | 结论 |
|------|------|------|
| 方案 1 | 操作列硬删除 + `DELETE /api/users/{id}` | **采用** |
| 方案 2 | 仅允许删已停用账号 | 未要求，多余步骤 |
| 方案 3 | 软删除 | 改动大，不符合「删掉账号」 |

## 接口设计

### `DELETE /api/users/{user_id}`

- 鉴权：`admin_required`
- 行为（同一事务）：
  1. 加载用户；不存在 → 404
  2. `role == admin` → 403「不能删除管理员账号」
  3. `user_id == 当前用户 id` → 400「不能删除当前登录账号」
  4. 统计未完成任务：`assignee_id == user_id` 且 `status in (待处理, 待审核, 已驳回)`；若 > 0 → 400「该账号仍有 N 条未完成任务，请先处理或改派后再删」
  5. 清理依赖（避免外键失败）：
     - 删除 `task_drafts` 中 `assignee_id == user_id` 的草稿
     - 将 `classification_tasks.assignee_id`（及可选的 `reviewed_by` 若等于该用户）置空
     - 将 `approved_products.approved_by` 中等于该用户的置空
     - 将日志类可空 `user_id` / `operator_id`（`operation_logs`、`field_change_logs`、`assignment_logs`、`review_logs` 等）置空；**不删除**日志行本身
     - 规则版本 `created_by`、系统配置 `updated_by` 等若等于该用户则置空
  6. 删除 `users` 行
  7. 写操作日志：`action=delete_user`，`detail` 含 `username`、`user_id`（注意：操作日志的 `user_id` 为执行删除的管理员；`target_id` 为被删用户 id。若先写日志再删用户，日志 `user_id` 指向管理员，无冲突）
  8. 提交事务
- 成功：返回成功消息；前端刷新列表

## 前端设计

- 文件：`frontend/src/views/admin/UserManage.vue`、`frontend/src/api/users.js`
- 操作列加宽；`v-if="row.role === 'operator'"` 显示危险样式「删除」
- 确认后调用 `deleteUserApi(row.id)`；成功 `ElMessage.success` 并 `loadUsers()`

## 异常与边界

| 情况 | 处理 |
|------|------|
| 用户不存在 | 404 |
| 删管理员 | 403 |
| 删自己 | 400 |
| 有未完成任务 | 400 + 条数 |
| 非管理员 | 403 |
| DB/外键失败 | 回滚 + 失败提示 |

## 测试要点

1. 无未完成任务的操作员 → 删除成功  
2. 有待处理/待审核/已驳回 → 拒绝  
3. 仅有已通过任务 → 可删，任务保留且 `assignee_id` 为空  
4. 删管理员 / 删自己 → 拒绝  

## 验收标准

- 操作列在停用后有「删除」，仅操作员可见  
- 确认后才删除  
- 有未完成任务时无法删且提示清楚  
- 管理员账号不可删；业务任务数据不因删人而整批消失  

## 非目标

- 不做软删除 / 回收站  
- 不批量删除  
- 不自动改派未完成任务（须管理员先处理）  
- 不删除操作员历史产生的业务任务/正式库记录本身
