# 无需填写字段规则设计

日期：2026-09-09  
状态：已确认，按方案 1 实施

## 背景

分类填写时，部分「大类」下某些字段业务上无需填写。现有分类规则只提供级联选项与手输能力，无法把指定字段置为不可用。  
补充表见 `需求相关/无需填写字段.xlsx`（仅按大类判断；表中「区隔」列忽略）。该补充规则优先级高于现有级联/补充规则。

## 需求结论

1. **匹配键**：仅按「大类」精确匹配；忽略 Excel「区隔」列。
2. **单元格为「无」**：对应字段填写控件不可用（灰掉）、已填值清空、暂存/提交存空。
3. **后端强制**：`save_draft` 与提交校验均拦截「禁用字段仍有值」；禁用字段免于现有必填校验。
4. **维护方式**：管理员单独导入入口；每次导入 **全量覆盖** 并生成新版本；查询只读最新版本。
5. **优先级**：禁用 > 现有级联选项 / 手输 / field-meta。
6. **未命中**：大类不在表中，或尚未导入补充表 → 行为与现在一致（全部可填）。

## 方案选择

| 方案 | 说明 | 结论 |
|------|------|------|
| 方案 1 | 独立版本表 + 独立导入 + 前端禁用/后端校验 | **采用** |
| 方案 2 | 写入现有分类规则体系 | 与级联规则耦合，优先级难维护 |
| 方案 3 | 前端写死/配置文件 | 管理员无法自助更新 |

## 数据模型

### `skip_field_rule_versions`

| 字段 | 说明 |
|------|------|
| id | 主键 |
| version_no | 版本号（唯一） |
| remark | 备注 |
| created_by | 导入人 |
| created_at | 导入时间 |

### `skip_field_rules`

| 字段 | 说明 |
|------|------|
| id | 主键 |
| version_id | 外键 → versions |
| category_large | 大类（精确匹配） |
| disabled_fields | JSON 数组，存中文列名，如 `["卷数","总入数"]` |
| is_active | 默认 true |

同一 `version_id` 下每个 `category_large` 至多一行。

### 中英文字段映射（API 对外用英文）

| 中文（Excel 列） | API / 任务字段 |
|------------------|----------------|
| 类别 | category_type |
| 主材质 | material_main |
| 辅材质 | material_aux |
| 包装方式 | packaging |
| 尺寸 | size |
| 卷数 | roll_count |
| 总入数 | total_count |

说明：大类、区隔本身不作为可禁用列参与本规则。

## 接口设计

### `POST /api/skip-field-rules/import`

- 鉴权：`admin_required`
- 上传 `.xlsx`；解析首个 Sheet
- 规则：
  - 第 1 行为表头，须含「大类」
  - 忽略「区隔」列
  - 行内大类为空 → 跳过
  - 其余列单元格值为「无」→ 记入该大类的 `disabled_fields`
  - 同一大类多行 → 禁用字段取并集（防御性；当前样例每大类一行）
- 行为：事务内新建 version + 写入全部 rules；旧版本保留作历史，生效以最新 version 为准
- 写操作日志：`import_skip_field_rules`
- 成功返回：`version_no`、`rule_count`、可选统计信息

### `GET /api/skip-field-rules/version`

- 鉴权：`login_required`
- 返回当前最新版本摘要；未导入 → `null` / 空数据（与分类规则 version 接口风格一致）

### `GET /api/skip-field-rules/disabled-fields`

- 鉴权：`login_required`
- 查询参数：`category_large`（必填；空则返回 `[]`）
- 返回：英文字段名数组，如 `["roll_count","total_count"]`
- 未导入或未命中 → `[]`

### 任务服务改动

- `save_draft`：根据草稿/任务中的大类查询禁用列表；若禁用字段有非空值 → 拒绝并提示「{中文名}无需填写」
- 提交前 `_validate_for_submit`（及更新分类字段的保存路径，若存在）：
  - 同样拦截禁用字段有值
  - 现有必填（如类别、区隔）：若该字段在禁用列表中，则 **跳过该必填项**
- 服务端 **不静默清空**：禁用字段一旦有非空值即拒绝（与已确认的强制校验一致）

## 前端设计

### 管理端

- 文件：`RuleManage.vue`（同页新增独立卡片）+ `api/skipFieldRules.js`
- 能力：选择 Excel → 导入 → 展示当前版本号与规则条数
- 与「分类规则」导入互不影响

### 填写端

- 复用点：`useClassificationCascade.js`、`ClassificationForm.vue`、操作员行内编辑
- 大类变更（含加载已有任务）时请求 `disabled-fields`
- 命中字段：
  - 控件 `disabled`
  - 立即清空当前值
  - 不请求/不展示该字段选项
  - 不参与前端必填提示
- 切换大类：仅对「新变为禁用」的字段清空；从禁用恢复为可填时不自动恢复旧值（保持空，由操作员重填）
- 缓存：可按规则版本 + 大类缓存禁用列表；补充表版本变化时失效

## 异常与边界

| 情况 | 处理 |
|------|------|
| 尚未导入补充表 | 全部可填 |
| Excel 某大类无任何「无」 | 该大类返回空禁用列表 |
| 大类名称与分类规则不一致 | 匹配失败 → 不禁用 |
| 非管理员导入 | 403 |
| 文件格式错误/缺「大类」列 | 400，提示明确 |
| 接口绕过前端 | 暂存/提交仍拒绝 |

## 测试要点

1. 导入样例 Excel → 版本与条数正确（约 12 个大类）
2. 大类=拖把类 → 卷数、总入数禁用并清空
3. 暂存/提交携带禁用字段值 → 被拒
4. 大类=湿巾类 → 类别等禁用；提交不因缺少类别失败（区隔等仍按原必填，除非也被禁用）
5. 未在表中的大类 → 不受影响
6. 再次导入更小集合 → 全量覆盖，旧大类规则不再生效

## 验收标准

- 管理员可单独导入「无需填写字段」表并看到版本
- 操作员按大类看到对应字段灰掉且无法填写
- 暂存与提交均无法保存禁用字段的值
- 禁用字段不阻塞因「必填」导致的提交失败
- 本规则优先于现有级联展示

## 非目标

- 不按区隔（或多选区隔）判断
- 不做版本回滚 UI / 回收站
- 不改审核列表的展示样式（保证入库为空即可）
- 不把本表合并进分类规则 Excel 导入
