# 操作员自助修改密码设计

日期：2026-09-01  
状态：已确认，按方案 1 实施

## 背景

当前仅管理员可在「用户管理」中为账号重置密码；操作员端（「我的分类任务」）只有用户名与退出，无法自行改密。需要支持操作员在已知原密码的前提下修改自己的密码。

## 需求结论

1. **谁可用：** 仅操作员（`role=operator`）。管理员不开放自助改密，仍用「用户管理 → 重置密码」。
2. **入口：** 操作员顶栏用户名旁「修改密码」→ 弹窗表单。
3. **表单字段：** 原密码、新密码、确认新密码（均为密码输入，可显示/隐藏）。
4. **新密码规则：** 至少 8 位，且同时包含字母和数字；不能与原密码相同。
5. **成功后：** 提示成功，保持当前登录态（不强制重登）。
6. **审计：** 写入操作日志 `change_password`。

## 方案选择

| 方案 | 说明 | 结论 |
|------|------|------|
| 方案 1 | 顶栏弹窗 + `POST /api/auth/change-password` | **采用** |
| 方案 2 | 独立账号设置页 | 本期多余 |
| 方案 3 | 复用管理员用户管理接口 | 权限与校验混杂，不安全 |

## 接口设计

### `POST /api/auth/change-password`

- 鉴权：`login_required`（需登录）
- 权限：当前用户 `role == operator`；管理员 → 403，提示「请使用用户管理重置密码」
- 请求体：

```json
{
  "old_password": "string",
  "new_password": "string",
  "confirm_password": "string"
}
```

- 校验顺序（失败立即返回 400，中文提示）：
  1. 三项均非空
  2. `new_password == confirm_password`，否则「两次输入的新密码不一致」
  3. 新密码长度 ≥ 8，且同时含字母与数字，否则「新密码至少 8 位，且需同时包含字母和数字」
  4. `check_password(old_password)` 通过，否则「原密码错误」
  5. 新密码与原密码不同（可用 `check_password(new_password)` 判断），否则「新密码不能与原密码相同」
- 成功：`set_password(new_password)`；写操作日志 `action=change_password`，`target_type=user`，`target_id=当前用户 id`；返回成功消息
- 不使现有 JWT 失效（与「保持登录」一致）

## 前端设计

- 文件：`frontend/src/views/operator/Layout.vue`、`frontend/src/api/auth.js`（或等价封装）
- 顶栏增加「修改密码」链接/按钮（与「退出」并列）
- `el-dialog` + 表单三字段；提交前本地校验一致性与强度，再调 API
- 成功：关闭弹窗、清空表单、`ElMessage.success`；失败：沿用 request 拦截器 / 表单提示
- 管理员 Layout **不**增加此入口

## 异常与边界

| 情况 | 处理 |
|------|------|
| 未登录 | 401 |
| 管理员调用 | 403 |
| 原密码错误 | 400 |
| 两次新密码不一致 | 400 |
| 强度不足 | 400 |
| 新密码与原密码相同 | 400 |
| 字段为空 | 400 |

## 测试要点

1. 操作员合法改密 → 成功；可用新密码登录  
2. 原密码错误 → 拒绝，密码不变  
3. 确认不一致 / 强度不够 / 与原密码相同 → 拒绝  
4. 管理员调用 → 403  

## 验收标准

- 操作员顶栏可打开改密弹窗并完成改密  
- 成功后无需重新登录  
- 错误提示明确  
- 管理员无此入口；管理员重置密码能力不变  

## 非目标

- 不做忘记密码 / 邮箱找回  
- 不强制改密后登出  
- 不把同一套强度规则强加到管理员「创建用户/重置密码」（本期仅自助改密接口强制；若后续统一可另开需求）  
- 不改操作员其他业务页面
